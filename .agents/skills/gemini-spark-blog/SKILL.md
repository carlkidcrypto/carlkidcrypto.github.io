# Gemini Spark Daily Blog Publishing Skill

This skill documents the automated/pair-programming procedure to ingest daily
blog post drafts produced by the **Gemini Spark Agent** in Google Drive (`Auto Blog Posts`),
transform them into publication-ready Sphinx articles for [carlkidcrypto.github.io](https://carlkidcrypto.github.io),
validate code snippets and theme compliance, open a GitHub Pull Request, and
communicate review status and feedback back to the Gemini Spark Agent via Google Drive.

### Critical Formatting Rules

> [!CAUTION]
> **Zero `.. contents::` Directives**: Never insert an in-page `.. contents::` directive.
> The **Furo** theme automatically generates the in-page table of contents in the right sidebar.
> An in-page `.. contents::` triggers a red theme warning banner in Furo and will fail the repository audit.

* **Section Underlines**: Use standard Docutils adornments in order:
  - Title: Overline and underline with `=`
  - H1 sections: `=`
  - H2 subsections: `-`
  - H3 sub-subsections: `~`
* **Code Blocks**: Specify language explicitly (e.g., `.. code-block:: python`, `.. code-block:: bash`).
* **Example Scripts & Download Links**:
  - Every runnable Python code example is automatically extracted and saved into `example_scripts/<slug>/<filename>` as a standalone, executable Python script (`chmod +x`).
  - Directly under each example code block in the article, include a raw download link:
    ```rst
    📥 `Download this script: <filename> <https://raw.githubusercontent.com/carlkidcrypto/carlkidcrypto.github.io/main/example_scripts/<slug>/<filename>>`_
    ```
  - Extraction and link synchronization is automatically handled during ingestion by `sync_drive_post.py --ingest` and by `validate_blog_code.py --save-examples`.
* **Cross-References**: Always use full external HTTPS URLs or Sphinx `:doc:` / `:ref:` directives.

See [references/blog_format_guide.md](./references/blog_format_guide.md) for full style guidelines.

### Code Testing & API Validation Standards

All code blocks in published articles must pass rigorous automated validation:
* **Python Syntax & Compilation**: Parsed with `ast.parse` and compiled with `compile(mode='exec', flags=PyCF_ALLOW_TOP_LEVEL_AWAIT)`. Coroutines returned from top-level await are executed and evaluated.
* **Modern ezsnmp API Standards**:
  - **No Legacy Imports**: Reject `import easysnmp` or `from easysnmp import ...`. Must use `ezsnmp`.
  - **Exception Hierarchy**: Use modern `ezsnmp.exceptions` classes exclusively. Net-SNMP error translation produces exactly 10 exceptions (all inheriting from `GenericError`):
    - `GenericError` (base class for all ezsnmp errors)
    - `ConnectionError` (socket setup / EngineID discovery failures)
    - `TimeoutError` (all retries exhausted with no response)
    - `NoSuchInstanceError` (object exists but specific index absent)
    - `NoSuchNameError` (OID name not found on remote agent)
    - `NoSuchObjectError` (requested MIB object unavailable)
    - `PacketError` (packet processing or formatting errors)
    - `ParseError` (parsing SNMP messages or arguments)
    - `UndeterminedTypeError` (returned ASN.1 type cannot be determined)
    - `UnknownObjectIDError` (unknown or unresolvable OID symbol)
    **CRITICAL**: `ezsnmp` does NOT prefix exceptions with `EasySNMP`. For example, `EasySNMPUndeterminedTypeError` DOES NOT EXIST in the repository—the correct class name is `UndeterminedTypeError`. Never use legacy `EasySNMP*` names in prose, diagrams, or code.
  - **Standardized Method Names**: Use snake_case `session.bulk_walk()` and `session.bulk_get()` (never `.bulkwalk()` or `.get_bulk()`).
  - **Method Signatures**:
    - `session.get()` accepts an OID string or list of OID strings (never tuple notation `('sysDescr', '0')`).
    - `session.walk()` accepts a single OID string.
    - `session.bulk_walk()` accepts OIDs; repetition limits are configured on the `Session(set_max_repeaters_to_num=25)` constructor.
  - **Result Handling**: `session.get()` returns a `tuple[Result, ...]`; unpack the scalar item before accessing properties: `var = session.get('sysDescr.0')[0]`.
  - **Result Attributes**: In ezsnmp Result objects, use `.index` and `.type` (never legacy `.oid_index` or `.snmp_type`).
  - **SNMPv2 Missing Instances**: `NOSUCHOBJECT` and `NOSUCHINSTANCE` are returned in `Result.type`, not raised as Python exceptions.
* **Runtime Test Execution**:
  - `validate_blog_code.py` mounts a sandbox test harness with simulated mock MIB responses (`sysDescr`, `ifDescr`, `ifHCInOctets`, `pethMainPsePower`, `dot1qPvid`, `bgpPeerState`, etc.).
  - Asserts complete runtime execution without `NameError`, `TypeError`, `AttributeError`, `KeyError`, or unhandled exceptions. Missing external third-party libraries (e.g. `pynetbox`, `duckdb`) are safely skipped, but any invalid `ezsnmp` import triggers a hard validation error.
* **Auto-Correction**:
  - Run `python3 .agents/skills/gemini-spark-blog/scripts/validate_blog_code.py --fix` to automatically upgrade legacy API patterns in draft code blocks, preserving comparison tables and historical prose.
* **Mandatory AI Disclaimer Footer**:
  - Ensure every article concludes with the standard warning admonition:
    ```rst
    ----

    .. warning::

       AI-generated content may contain misinformation or mistakes. A human does review this, but we are only human.
    ```

## Step 4.5: Content Review & Gemini Spark Quality Gate

When reviewing content generated by the **Gemini Spark Agent**, rigorously inspect and correct the following recurring patterns:

1. **Furo Theme Structural Invariants**:
   - **Zero `.. contents::` Directives**: Strip out any `.. contents::` or `.. contents:: Table of Contents`. Furo generates the TOC in the sidebar; in-page directives display a red theme warning banner.
   - **Header Formatting**: Replace raw field lists (`:Date:`, `:Author:`, `:Estimated Reading Time:`) with standard Sphinx `.. meta::` and `.. note::` metadata blocks.

2. **Technical Accuracy & Architecture**:
   - **`Session.bulk_walk()` Parameters**: Accepts only OID strings (never pass `max_repetitions=25`, which raises `TypeError`). Configure repeater counts on `Session(set_max_repeaters_to_num=25)` and update prose to describe session-level configuration. Repetition counts tune batch sizing per PDU, not total round-trips.
   - **`Session.get()` Unpacking**: Always returns `tuple[Result, ...]`; unpack the scalar element (`session.get("sysDescr.0")[0].value`).
   - **`Session.set()` Values & Error Handling**: Values in the triple vector must be passed as strings (e.g. `[target_oid, 'i', str(int_value)]`). Nonzero agent response `errstat` codes (e.g. `notWritable`, `wrongValue`) raise `ezsnmp.exceptions.PacketError`, not separate exception subclasses.
   - **Net-SNMP Concurrency**: Net-SNMP maintains process-global C state protected by internal mutexes. High concurrency must use `ProcessPoolExecutor` or bounded thread pools ($\le 4$ worker threads per Python process) to avoid lock contention. Never claim fine-grained per-session mutexes eliminate global contention.
   - **Session Rebuilding in C++**: A single `Session` instance rebuilds its `m_args` vector on each call and cannot be used concurrently across multiple threads without an `asyncio.Lock()` or mutex.
   - **Native Return Types & Exception Mappings**: `SessionBase::get` returns native `std::vector<Result>`, exposed through SWIG as `ezsnmp.Result` objects (never legacy `SNMPVariable`). In `snmpset.cpp`, unsupported SET types raise `UndeterminedTypeError`.
   - **Hex-STRING Bitmask Decoding**: For binary `PortList` or MAC address attributes formatted as hex text (e.g., `'80 00'`), decode via `bytes.fromhex(val.replace(' ', ''))` before evaluating bit positions rather than using `.encode('latin1')`.
   - **LLDP & Topology Discovery**: LLDP composite table indices contain `[time_mark].[local_port].[rem_idx]`; recover full suffixes using `.oid` and `.index`. Map local ports using `lldpLocPortDesc` (matching the local-port table space), not `ifDescr`. Query both LLDP and CDP and deduplicate rather than falling back only when LLDP is empty.
   - **Metrics Exporters (Prometheus / OTel)**: Include `if_index` in Prometheus labels to ensure unique time series per port. In OpenTelemetry, register cumulative monotonic byte counters (`ifHCInOctets`) as `ObservableCounter`, never `ObservableGauge`. Standalone snippets must install `MeterProvider` and a periodic reader.
   - **Telemetry Sampling vs Microbursts**: 1–5s polling captures interval-average throughput and link saturation trends, not sub-second microbursts or buffer drops (which require queue watermarks or streaming sFlow/IPFIX). Distinguish zero-copy in-memory Arrow queries from Parquet disk serialization and compression overhead.
   - **Monotonic Clocks**: Circuit breakers, cooldown periods, and polling timers must use `time.monotonic()` instead of `time.time()` to prevent DST, NTP, and timezone clock adjustments from corrupting deadlines.
   - **Default Timeout Sizing**: Note that ezsnmp defaults to a 1s timeout and 3 retries (total ~4s wait). Uncalibrated 5s/5-retry configurations block threads for up to 30s per dead host.
   - **Table Consistency**: Note that independent walks across multiple table columns gather each column sequentially; in rapid interface churn, verify row completeness rather than assuming atomicity or index continuity.
   - **No False Drop-in Claims**: Detail the modern API differences (`Result` tuple return, `.index`/`.type` attributes, `bulk_walk` naming) rather than claiming 100% drop-in compatibility with Easy SNMP.
   - **RFC 3433 Sensor MIB**: Use standard `entPhySensor*` columns. Compute scale factor exponent as `(scale - 9) * 3`. Celsius is enum value 8 (distinguishing from Hertz at 7).
   - **BGP Telemetry**: `Active(3)` state is actively attempting TCP connection establishment before OpenSent. Reconstruct 4-octet IPv4 peer IP dynamically.
   - **VRRP / HSRP HA Telemetry**: Cross-reconcile gateway pairs concurrently; extract VRID from `[ifIndex].[vrid]`; detect split-brain and no-master states.
   - **Network Time (NTP/PTP)**: Batch scalar lookups in a single `session.get([...])`; alert on expanding root dispersion before sync fails; use `time.monotonic()` for timers.
   - **Traffic Flow (NetFlow/IPFIX)**: Query scalar exporter drop/export counters via `session.get()`, active flow tables via `bulk_walk()`.
   - **PurpleAir Ecosystem**:
     * `purpleair_api`: Use `post_create_group_data(name=...)` (not `post_create_group`) and `request_members_data(group_id=...)` (not `request_group_data`).
     * `purpleair_data_logger`: `PurpleAirPSQLDataLogger` constructor takes `pg8000.connect(...)` connection object; auto-configures TimescaleDB hypertables, compression policies, and continuous aggregates.
     * `purpleair-matterbridge`: Matter 1.5.1 clustering requires Docker `network_mode: host` for mDNS and IPv6 discovery.
   - **Centralized Findings & Guidelines Reference**: Refer to `COMMON_REVIEW_FINDINGS_AND_GUIDELINES.rst` in Google Drive (`Auto Blog Posts/`) for the comprehensive live catalog of all architectural findings and review feedback.

## Step 5: Multi-Agent Git Worktree Concurrency, Branching & PR Creation

To avoid stepping on other concurrent agents (maintainer, background agentic workflows, Copilot):

1. **Pre-flight Active Worktree Discovery & Sibling Directory Placement**:
   Always discover active worktrees (`git worktree list`) and create dedicated worktrees in sibling directories (e.g. `../wt-carlkidcrypto-<task>`):
   ```bash
   git fetch origin
   git worktree add -b feature/blog-<slug> ../wt-carlkidcrypto-<slug> origin/main
   cd ../wt-carlkidcrypto-<slug>
   ```
   **Primary Checkout Root Immutability**: Never switch branches or leave dirty files in the primary checkout root (`carlkidcrypto.github.io`). Keep it clean on `main`.

2. **Extract Example Scripts & Insert Download Links**:
   Run the code extraction workflow to generate standalone runnable scripts under `example_scripts/<slug>/` and insert raw download links in the RST article:
   ```bash
   python3 .github/scripts/validate_blog_code.py --post <slug>
   black example_scripts/<slug>/
   ```

3. **Targeted Staging & Atomic Commit**:
   Use targeted staging only—never blanket `git add .` or `git add -A`:
   ```bash
   git add source/blog/<slug>.rst source/blog/index.rst source/blog/category-<name>.rst example_scripts/<slug>/
   git commit -m "feat(blog): add <topic> blog post" -m "Co-authored-by: Gemini 3.8 Flash <gemini@google.com>"
   ```

4. **Push Branch & Open Pull Request**:
   ```bash
   git push -u origin feature/blog-<slug>
   gh pr create \
     --title "feat(blog): add <topic> blog post" \
     --body "## Summary
   - Adds technical blog post: '<Article Title>' (\`source/blog/<slug>.rst\`).
   - Updates \`source/blog/index.rst\` with toctree registration and responsive grid card.
   - Extracted runnable example scripts to \`example_scripts/<slug>/\` with raw download links.
   - Passed \`audit_blog_posts.py\` (Rule 7) and \`sphinx-build -W\` with zero warnings.

   Co-authored-by: Gemini 3.8 Flash <gemini@google.com>"
   ```

5. **Maintainer-Only PR Merging Policy**:
   Never merge pull requests into `main` (`gh pr merge`). Merging is strictly reserved for the maintainer (`@carlkidcrypto`).

6. **Clean Worktree Pruning**:
   Once the PR is submitted, clean up the dedicated worktree:
   ```bash
   cd ../carlkidcrypto.github.io
   git worktree remove ../wt-carlkidcrypto-<slug>
   git worktree prune
   ```

## Step 7: Stacked PR Merging & Rebase Protocol

When pull requests are stacked sequentially (e.g., PR #20 stacked on PR #19, PR #21 stacked on PR #20), merging an upstream PR on GitHub creates a new squashed or rebased commit on `main`. Because the commit hashes change, naive rebasing (`git rebase main`) causes merge conflicts by attempting to replay the already-merged upstream commits.

### The Mathematical Rebase Scheme (`git rebase --onto`)
To seamlessly rebase stacked PRs without conflicts:
1. **Transplant the new root PR onto `main`**:
   ```bash
   git checkout <next_root_branch>
   git rebase --onto main <old_merged_head> <next_root_branch>
   gh pr edit <next_root_pr> --base main
   ```
2. **Cascade down the remaining stack**:
   For each child branch $k$ stacked on parent $k-1$:
   ```bash
   git checkout <child_branch>
   git rebase --onto <parent_branch> <old_parent_sha> <child_branch>
   ```
3. **Push with Lease**:
   ```bash
   git push --force-with-lease origin <branch>
   ```

### Automated Rebase Tool
Use the included automated rebasing tool to rebase the entire remaining stack with a single command:

```bash
# Preview the rebase plan:
python3 .agents/skills/gemini-spark-blog/scripts/rebase_stack.py --dry-run

# Execute rebase across all stacked branches and force-push:
python3 .agents/skills/gemini-spark-blog/scripts/rebase_stack.py --push

# Alternatively via the sync helper:
python3 .agents/skills/gemini-spark-blog/scripts/sync_drive_post.py --rebase-stack --push
```

See [references/stacked_pr_merging_guide.md](./references/stacked_pr_merging_guide.md) for full technical details.
